# Evermap model reference

The JSON Schemas in `assets/schema/` are normative; this page gives every shape they define, so
you never need to read them.

## Layout

```
.evermap/
├── evermap.json              manifest: system, synced commit, scope, coverage
├── model/<kind-dir>/<slug>.json
│     components operations entities channels workflows rules invariants roles
├── decisions/<slug>.json     decision records (never regenerated)
├── proposals/<slug>/         optional overlay: proposal.json + model/… (lifecycle: proposed)
└── views/                    generated by render; never edit
```

## Ids

`kind:slug`. A slug is lowercase segments of `[a-z0-9]` joined by `-`, scoped with dots:
`operation:parcel.collect`, `rule:collection.window`. The file lives at the path the id gives
(`.evermap/model/rules/collection.window.json`); decisions go in `.evermap/decisions/`.

- Name ids after the domain concept, never after a file or function.
- Ids never change when code is renamed or moved. If the concept itself is renamed, split or
  merged, the new element lists the old ids in `aliases`. Retired ids are never reused.
- Parts use `#`: `entity:parcel#status` (field), `workflow:deposit-parcel#s2` (step),
  `operation:parcel.deposit#tx1` (transaction).

## Shapes

`"k"` is required and `"k?"` optional. `"a|b"` lists every allowed value. `[X]` is a list of X.
Capitalised names are defined below. `+A` adds the `Annotation` fields; without them an
attribute inherits the element's provenance.
`+E` adds the envelope; a field written next to it replaces the envelope's version. Other words
are hints: `id` is `kind:slug`, `ref` is an id or `id#part`, `text` is a non-empty string,
`glob` a repository-relative glob. No other keys are allowed.

- `Envelope`: {"id": id, "kind", "name", "summary", "plain?", "parent?": id, "lifecycle": "implemented|proposed|deprecated", "provenance": "observed|inferred|stated|unknown", "rationale?", "evidence?": [Evidence], "relations?": [Relation], "aliases?": [id], "tags?": [text]}
- `Annotation`: {"provenance?": "observed|inferred|stated|unknown", "rationale?", "evidence?": [Evidence]}
- `Evidence`: {"type": "code|config|schema|test|doc|commit|stated", "path?", "symbol?", "lines?": [int], "hash?", "commit?", "who?", "date?", "source?", "note?"}
- `Relation`: {"type": "depends_on|calls|reads|writes|deletes|publishes|consumes|applies|uses_role", "target": id, "mechanism?", "fields?": [text], "message?": id, "condition?", "in_transaction?", +A}
- `Param`: {"name", "type?", "required?": bool, "source?": "path|query|body|header|message|arg", "validation?", "maps_to?": ref, "plain?", +A}
- `Error`: {"condition", "signal", "plain?", +A}
- `Field`: {"name", "type?", "nullable?": bool, "plain?", "sensitivity?": "none|pii|financial|credential-reference", "origins?": [Origin], "states?": {"values": [text], "transitions?": [{"from", "to", "via?": id, "guard?": id, +A}]}, +A}
- `Origin`: {"type": "user-input|derived|system-generated|external|copied|constant", "from?": [ref], "via?": id, "transform?", +A}
- `Section`: {"text", "provenance": "confirmed|inferred|unknown"}
- `component`: {+E, "type": "service|worker|frontend|module|library|datastore|external-system", "technology?", "paths?": [glob], "responsibilities?": [text], "config?": [{"name", "kind": "env|file|flag|secret|other", "purpose?", +A}]}
- `operation`: {+E, "parent": id, "trigger": {"type": "http|rpc|message|schedule|webhook|cli|call|startup", "detail?", "channel?": id, +A}, "exposure": "public|internal|unreachable", "contract?": {"input?": [Param], "output?": [Param], "errors?": [Error], "spec?": Evidence}, "auth?": {"authentication": "required|optional|none|unknown", "mechanism?", "authorization?": [{"rule", "roles?": [id], "ownership_check?": bool-or-null, +A}], +A}, "transactions?": [{"id", "mechanism", "isolation?": "default|read-committed|repeatable-read|serializable|unknown", "note?", +A}], "concurrency?": [{"resource": ref, "mechanism": "row-lock|optimistic-version|unique-constraint|atomic-update|conditional-update|advisory-lock|single-consumer|none-detected", "note?", +A}], "idempotency?": {"mechanism": "idempotency-key|natural-key|dedupe-record|conditional-update|none-detected|not-applicable", "key?", "note?", +A}, "failure_handling?": [{"on", "behaviour": "retry|compensate|propagate|swallow|dead-letter|mark-failed", "plain?", +A}]}
- `entity`: {+E, "type": "table|collection|document|cache-key|file|message|dto", "fields?": [Field], "constraints?": [{"type": "primary-key|unique|foreign-key|check|exclusion|not-null", "fields?": [text], "detail?", "references?": ref, +A}]}
- `channel`: {+E, "type": "queue|topic|outbox|webhook|schedule|stream|email", "message?": id, "delivery?": "at-least-once|at-most-once|exactly-once-claimed|unknown", "ordering?": "none|per-key|total|unknown"}
- `workflow`: {+E, "actors?": [id], "trigger_plain?", "data_collected?": [ref], "steps": [{"id", "plain", "operation?": id, "rules?": [id], "next?": [text], "outcome?", "branches?": [{"condition_plain", "next?", "outcome?", +A}], "on_failure?": [{"plain", "next?", "outcome?", +A}], +A}], "outcomes": [{"id", "type": "success|alternative|failure", "plain"}]}
- `rule`: {+E, "type": "validation|eligibility|calculation|policy|state-transition", "statement", "parameters?": [{"name", "value": string-number-or-bool, "source?": Evidence}]}
- `invariant`: {+E, "statement", "category": "uniqueness|referential|consistency|authorization|idempotency|ordering|temporal|conservation", "scope?": [ref], "enforcement": [{"mechanism": "db-constraint|transaction|lock|conditional-update|application-check|idempotency-key|test-only|none-detected", "where?": ref, "note?", +A}], "verified_by?": [Evidence], "criticality?": "high|medium|low"}
- `role`: {+E, "type": "user-role|service-identity|external-actor"}
- `decision`: {"id": id, "kind", "title", "status": "proposed|accepted|rejected|deprecated|superseded", "date?": date-or-null, "problem": Section, "drivers?": [Section], "options?": [{"name", "outcome": "chosen|rejected|not-chosen", "pros?": [text], "cons?": [text], "reasons_rejected?": Section, "provenance?": "confirmed|inferred|unknown"}], "decision": Section, "consequences?": [{"text", "type": "positive|negative|neutral", "provenance": "confirmed|inferred|unknown"}], "affects?": [ref], "supersedes?": [id], "superseded_by?": [id], "evidence?": [Evidence], "aliases?": [id], "tags?": [text]}
- `manifest`: {"schema_version", "system": {"name", "summary?", "plain?"}, "synced": {"commit", "mode": "init|update|regenerate", "dirty?": bool}, "scope": {"include": [glob], "exclude?": [glob]}, "coverage?": {"unmapped?": [{"path": glob, "reason"}], "pending?": [id], "limitations?": [text]}, "views?": {"diagrams?": ["excalidraw|eraser"], "kinds?": ["sequence|er|state|access"]}}
- `proposal`: {"title", "description?", "status": "draft|assessed|accepted|abandoned", "source?": {"who?", "date?"}}

Fields that need more than their shape:

- `plain` is required for component, operation, workflow, rule, invariant and role: plain words,
  at most 600 characters, no code identifiers, nothing the technical fields do not support.
- `lifecycle: proposed` exists only inside a proposal overlay.
- Operation `parent` is the owning component; a persisted entity's is its datastore.
- `none-detected` means "looked and found nothing" and needs evidence or a rationale. A field left
  out means "not assessed". A `stated` invariant with `none-detected` enforcement is a finding.
- `paths` are globs of the code a component owns: they map changed files to components.
- `config` and `parameters` hold names and non-secret business constants, never secrets.
- Workflow steps reference an operation or a rule, or carry evidence; `next`, branch and outcome
  ids resolve inside the workflow. `in_transaction` names a transaction `id` of the operation.

## Provenance

- `observed`: evidence directly shows the claim. At least one non-`stated` evidence item.
- `inferred`: reasoned from naming, convention, configuration, tests or dynamic dispatch.
  Needs `rationale`, and should still cite what it reasoned from.
- `stated`: a human said so. Needs a `stated` evidence item.
- `unknown`: expected but not determinable. The element records the gap.

## Evidence

```json
{"type": "code", "path": "api/collect.py", "symbol": "collect_parcel", "lines": [10, 17], "note": "conditional status update"}
```

- File types (`code`, `config`, `schema`, `test`, `doc`) need `path` and `lines`; `commit`
  needs `commit` (a full SHA); `stated` needs `who` (a role or handle, never an email), `date`
  given by the human, and `source` (`conversation`, a repository path or an issue URL).
- `path` is repository-relative with `/`. `lines` is `[start, end]`, 1-based and inclusive.
  `note` is at most 200 characters.
- `hash` is written by `anchor` or `apply`. Leave it out.
- Never copy code, values or secrets into the model. It holds locations, not excerpts.
- `check-evidence` states: `fresh`; `moved` (the identical span is elsewhere in the file or its
  rename target; `--fix-moved` rewrites `path` and `lines`); `stale` (the span changed, or occurs
  more than once); `missing` (the file is gone, or the symbol is no longer in it). Re-read stale
  claims in the code, then `anchor <id> --refresh`.

## Decisions

Any status other than `proposed` needs `decision.provenance: confirmed`, and any confirmed
section needs a `stated` evidence item (or the `doc` item of an accepted record in the
repository). `inferred` sections are shown as "Inferred — not confirmed". Never upgrade to
`confirmed` without the human's confirmation recorded as `stated` evidence.

## Relations

Stored on the source element only.

| Type | Source → target |
| --- | --- |
| `depends_on` | component → component (`mechanism`: http, grpc, sql, sdk, in-process, queue) |
| `calls` | operation → operation (`mechanism`: sync-http, sync-call, async-via-outbox, async-message) |
| `reads`, `writes`, `deletes` | operation → entity |
| `publishes`, `consumes` | operation → channel |
| `applies` | operation → rule |
| `uses_role` | role → role (hierarchy) |

`enforces` and `affects` are derived from `invariant.enforcement[].where` and
`decision.affects`. Never store them. An observed relation that the target's evidence does not
prove carries its own evidence (the line of the call).

Direction: `depends_on` points from the consumer to the provider (a frontend depends on the
service it calls). `calls` points from the caller to the callee, and its evidence is the line
in the caller's code that invokes it, never a signature or a comment. A client that sends an
HTTP request calls the server's handler, never the reverse. Data received as an argument is
not a call. Wrong (on the handler, citing its own signature), then right (on the client):

```json
{"type": "calls", "target": "operation:app.send-deposit", "evidence": [{"type": "code", "path": "api/deposit.py", "lines": [4, 4]}]}
```

```json
{"type": "calls", "target": "operation:parcel.deposit", "mechanism": "sync-http", "evidence": [{"type": "code", "path": "app/deposit.ts", "lines": [12, 12]}]}
```

## Validation rules

V1 schema; V2 ids, paths and aliases; V3 references resolve; V4 provenance needs evidence or
rationale; V5 no `proposed` in `model/`; V6 evidence paths, lines and hashes; V7 stale evidence
(error with `--strict`); V8 workflow steps; V9 secret scan; V10 `plain` text (warning); V11
decision rules; V12 decisions referencing removed ids (warning); V13 formatting (error with
`--strict`); V14 conflict markers; V15 views out of date (warning); V16 relation direction
(warning).

## Commands

`init`, `status`, `changes`, `estimate`, `packet`, `apply`, `anchor`, `check-evidence`, `fmt`, `validate`,
`sync`, `query` (`neighbors`, `impact`, `lineage`, `shared-resources`, `refs`), `search`,
`coverage`, `diff`, `render`. Each has `--help`.

## Example: a parcel-locker service

`.evermap/model/components/locker-api.json`

```json
{
  "id": "component:locker-api",
  "kind": "component",
  "name": "Locker API",
  "summary": "HTTP service for parcel deposits and collection.",
  "plain": "Lets couriers drop parcels off and recipients pick them up.",
  "type": "service",
  "technology": "python",
  "paths": ["api/**"],
  "config": [{"name": "DATABASE_URL", "kind": "env", "purpose": "Database location"}],
  "lifecycle": "implemented",
  "provenance": "observed",
  "evidence": [{"type": "code", "path": "api/routes.py", "symbol": "register", "lines": [6, 8]}]
}
```

`.evermap/model/operations/parcel.collect.json`

```json
{
  "id": "operation:parcel.collect",
  "kind": "operation",
  "name": "Collect parcel",
  "summary": "Checks the pickup code and expiry, then marks the parcel collected and frees the locker.",
  "plain": "A recipient enters their code and takes the parcel, unless it has expired.",
  "parent": "component:locker-api",
  "trigger": {"type": "http", "detail": "POST /parcels/<id>/collect"},
  "exposure": "public",
  "contract": {"input": [{"name": "code", "type": "text", "required": true, "source": "body"}],
               "errors": [{"condition": "wrong pickup code", "signal": "throws PermissionError", "plain": "The code is wrong."},
                          {"condition": "parcel expired", "signal": "throws ValueError", "plain": "The parcel waited too long."}]},
  "auth": {"authentication": "none"},
  "idempotency": {"mechanism": "conditional-update", "provenance": "inferred",
                  "rationale": "The update only matches a stored parcel, so a repeated request changes nothing.",
                  "evidence": [{"type": "code", "path": "api/collect.py", "symbol": "collect_parcel", "lines": [16, 16]}]},
  "failure_handling": [{"on": "wrong code or expired parcel", "behaviour": "propagate", "plain": "The request is refused."}],
  "lifecycle": "implemented",
  "provenance": "observed",
  "evidence": [{"type": "code", "path": "api/collect.py", "symbol": "collect_parcel", "lines": [10, 17]}],
  "relations": [{"type": "applies", "target": "rule:collection.window"}]
}
```

`.evermap/model/rules/collection.window.json`

```json
{
  "id": "rule:collection.window",
  "kind": "rule",
  "name": "Collection window",
  "summary": "A parcel expires a fixed number of days after it was stored.",
  "plain": "A parcel can only be collected for seven days.",
  "type": "eligibility",
  "statement": "days since storage must not exceed max_days",
  "parameters": [{"name": "max_days", "value": 7}],
  "lifecycle": "implemented",
  "provenance": "observed",
  "evidence": [{"type": "code", "path": "api/collect.py", "symbol": "is_expired", "lines": [3, 7]}]
}
```

`.evermap/decisions/conditional-collect-update.json`

```json
{
  "id": "decision:conditional-collect-update",
  "kind": "decision",
  "title": "Guard collection with a conditional update",
  "status": "proposed",
  "date": null,
  "problem": {"text": "Two collect requests for one parcel could both succeed.", "provenance": "inferred"},
  "decision": {"text": "Only update a parcel that is still stored.", "provenance": "inferred"},
  "affects": ["operation:parcel.collect"],
  "evidence": [{"type": "code", "path": "api/collect.py", "symbol": "collect_parcel", "lines": [16, 16]}]
}
```

The decision is a `proposed` candidate with inferred text: nobody has confirmed why the code
works this way. Written as one JSON array to `.evermap/draft.json` and passed to `apply`, these
four elements are written, anchored, formatted and validated in one step.
